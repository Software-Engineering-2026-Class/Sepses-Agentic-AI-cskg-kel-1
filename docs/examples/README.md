# Raw Input and RDF Output Examples

This directory provides one compact raw input example for each supported
cybersecurity datasource and the corresponding RDF/Turtle generated by the
current parser and SEPSES ontology mapper.

The raw samples are copied from `tests/fixtures/` and are intentionally small so
they can be reviewed in pull requests. The RDF files are generated artifacts,
not hand-authored Turtle.

## Example Matrix

| Datasource | Raw input | RDF output | Parser |
|---|---|---|---|
| CVE / NVD | `raw/cve_sample.json` | `rdf/cve_sample.ttl` | `CVEParser` |
| CWE | `raw/cwe_sample.xml` | `rdf/cwe_sample.ttl` | `CWEParser` |
| CPE | `raw/cpe_sample.json` | `rdf/cpe_sample.ttl` | `CPEParser` |
| CAPEC | `raw/capec_sample.xml` | `rdf/capec_sample.ttl` | `CAPECParser` |
| MITRE ATT&CK | `raw/attack_sample.json` | `rdf/attack_sample.ttl` | `MitreAttackParser` |
| ICSA | `raw/icsa_sample.csv` | `rdf/icsa_sample.ttl` | `ICSAParser` |

## Regenerate Examples

Run the generator after changing parser or mapper behavior:

```bash
python scripts/generate_example_rdf.py
```

The command rewrites `docs/examples/raw/` and `docs/examples/rdf/` from the
fixture files in `tests/fixtures/`.

## Validation

The example files are covered by `tests/test_examples.py`, which checks that:

- every datasource has a raw input file and RDF output file,
- every RDF output parses as valid Turtle,
- regenerated examples are graph-equivalent to the committed RDF files,
- shared relationship names are emitted in the correct source namespace.
